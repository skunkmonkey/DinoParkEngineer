# Curriculum Content implementation guide

The Phase 5 opening foundation is exposed only through
`src/curriculum-content/public.ts`. It is declarative, exact-versioned content;
copy never decides behavior. `createOpeningCurriculumPackage()` supplies the
signed dawn package, and `validateCurriculumPackage()` validates it against an
explicit inventory of domain references, entity IDs, and approved runtime
assets.

## Opening contract

The package fixes the dawn scenario to seed `1601`, a closed pre-opening park,
a pausable tick-300 visitor deadline, one unassigned partially configured first
feeding, and a successful first outcome. The second enclosure's automatic
closer is visibly disabled. The maintenance knowledge record is represented by
an explicit unavailable route and is absent from the second job's Worker
Context. Reuse therefore points to one deterministic stabilized near miss with
zero injuries and fatalities.

The incident links expected, observed, consequence, immediate causal gap,
affected entities, a Trace, and the responsible Prompt. The minimum recovery
surface offers two valid approaches: route maintenance Context or revise the
instruction. It includes a zero-authoring-cost Eval, candidate, Review,
intentional Deployment, successful rerun, park-open outcome, expressive reward,
and a Handbook entry that is explicitly ineligible for Agent Context.

## D2 asset handshake

The opening requires `assets:bundle-mvp-park@1.0.0` and these exact runtime
assets at `1.0.0`: operational-warning cue, herbivore dinosaur, dust effect,
grass-path environment, enclosure gate, dinosaur-plushie reward, park Worker,
park overview thumbnail, and park visitors. D3 does not read files or infer
availability from paths. D2 or integration code must supply those identities in
the validation inventory; a missing bundle or asset blocks the package with a
stable diagnostic.

## Validation

Validation covers boundary schemas, canonical fingerprint, exact class/schema
references, entity availability, unlock reachability and cycles, transfer and
playtest links, stable copy IDs, accessible guidance, asset readiness, Handbook
separation, and the exact golden chain:

1. first feeding succeeds;
2. the missing-context near miss is stabilized without casualty;
3. the free Eval passes;
4. the exact reviewed Deployment reruns successfully; and
5. the player opens the park intentionally.

This slice has no browser route or visual behavior. Browser verification begins
when Player Experience consumes the validated package; its cues and actions
must then be checked in connected Chrome per `AGENTS.md`.
